Methods, Results and Discussion: Comparing Sorting Algorithm Performance

Methods
We implemented three sorting algorithms in Python 3.11: insertion sort, merge sort and quicksort with a randomly chosen pivot. Each algorithm was tested on arrays of integers of sizes 1,000, 5,000, 10,000, 50,000 and 100,000. For each size we generated three types of input: randomly ordered values, values already sorted in ascending order, and values sorted in descending order. Each combination was run ten times, and we recorded the mean execution time using the time.perf_counter function. Insertion sort was not run on the two largest sizes because the expected running time was impractical.

Results
On random input, merge sort and quicksort both scaled approximately as n log n. Quicksort was consistently faster, taking on average 0.21 seconds for 100,000 elements compared with 0.34 seconds for merge sort. Insertion sort grew quadratically, taking 4.8 seconds for 10,000 elements. On already sorted input, insertion sort was the fastest of all three algorithms for every size tested, completing 10,000 elements in under 0.01 seconds. On reverse-sorted input, insertion sort showed its worst-case behaviour, while merge sort and quicksort were largely unaffected because of the random pivot choice.

Discussion
The results agree with the theoretical complexity of each algorithm. Quicksort's advantage over merge sort on random data can be explained by lower constant factors and better use of memory, since our merge sort implementation created new lists at each level of recursion. The strong performance of insertion sort on sorted data demonstrates why it is often used for small or nearly sorted arrays, and why hybrid algorithms such as Timsort combine it with merge sort.

There were several limitations. Timing measurements in Python are affected by background processes and interpreter overhead, so the absolute times should not be compared with implementations in compiled languages. We also did not measure memory usage, which would have highlighted another trade-off between merge sort and in-place quicksort. Future work could repeat the experiment with a larger range of input distributions, including arrays with many duplicate values.
